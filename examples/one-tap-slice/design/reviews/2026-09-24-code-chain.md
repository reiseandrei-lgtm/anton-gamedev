# Code review — chain

**CONCERNS.** Правила R1–R5, формула F1 и edge cases E1–E3 реализованы в коде и покрыты тестами, литералов-knob нет. Главная проблема: «душа» системы («каждый промах объясним», «фонари появляются за кадром») не защищена. Нижняя граница зазора не связана с минимальным прыжком hop. При chain#K1 из безопасного диапазона (0.5…0.8) генератор строит зазоры, на которые нельзя приземлиться. Появление фонарей за кадром держится на совпадении K3·K1 и ширины камеры, и тест это не проверяет.

## Pass 1 — критичное
Pass 1 FAIL-находок в изменённом коде нет. Ниже — унаследованные проблемы на путях, которые этот diff переподключил. Они не блокируют diff, но их стоит завести отдельной задачей до T-slice-30 (10 мин игры).
- `Presentation/GameBootstrap.cs:98-117` + `:174-178` (`Paint`) — каждый новый фонарь (на каждое приземление, через `LanternAdded`) создаётся через `CreatePrimitive` и получает `new Material(Shader.Find(...))`. При рестарте `Destroy(v.Body)` (`:87`) уничтожает объект, а материал остаётся. Сцена по архитектуре не перезагружается, поэтому материалы копятся всю сессию. Фонари позади игрока в течение забега тоже не удаляются. → На мобильном растёт память и число объектов, и это бьёт по B1 (кадр p95) на длинной сессии. → Пул из K3 + 2 view: фонарь, ушедший за левый край кадра, переставлять вперёд. Один общий материал на роль (`sharedMaterial`), цвет задавать через `MaterialPropertyBlock`.
- `Presentation/GameBootstrap.cs:138` → `:177` — `Paint` вызывается в `Update` каждый кадр, а `r.sharedMaterial.name` на каждом вызове создаёт новую строку. → Постоянный GC-мусор в кадре на мобильном. → Кешировать `Renderer` текущего фонаря и менять цвет через `MaterialPropertyBlock` без чтения `name`. Строку проверки `gd_` вызывать только при спавне.
- `Tests/PlayMode/ChainSceneTests.cs:19-24` — teardown удаляет `go`, камеры и `PlayerHop`, но не фонари и искры: `Spawn` создаёт их без родителя (`GameBootstrap.cs:101, 109`). → Цилиндры и кубы с коллайдерами остаются в сцене и загрязняют следующие PlayMode-тесты (`PlayerHopInputTests`) и визуальные эталоны. → В `Spawn` ставить `body.transform.SetParent(transform)` (и искру тоже) или удалять views в `OnDestroy` у `GameBootstrap`.

## Pass 2 — информационное
- `ChainGenerator.cs:41, 47` — предупреждения E1/E2 печатаются на каждом рестарте, потому что генератор создаётся заново в `StartRun`. При ошибочном конфиге консоль засыпается одинаковыми строками. Лучше проверять один раз, в `OnValidate` у `ChainConfig` или при первом создании.
- `ChainGenerator.cs:37` / `ChainTests.cs` — отсутствие E1 при значениях по умолчанию держится на том, что `4f − 0.35f` во float в точности равно `3.65f`. Сейчас это так, но совпадение хрупкое. Сравнивать с допуском (`MaxGap > reach + 1e-5f`).
- `ChainConfig.cs:12`, `architecture.md` Config map — диапазон K4 указан как `0..2^31`, а `int` вмещает максимум 2^31 − 1. Отрицательный seed не валидируется. Вопрос дизайнеру: зафиксировать `0..2^31−1`.
- `ChainGenerator.cs:57` — при K3 ≤ 0 (вне safe range) впереди нет фонарей, и `GapAfter(current)` (`GameBootstrap.cs:76`) бросает `ArgumentOutOfRange` на первом прыжке. Кламп `lookahead ≥ 1` с предупреждением.
- `ChainGenerator.cs:18, 50` — `lock` вокруг `SeedSource` не нужен: генератор создаётся только на главном потоке. Лишний код.
- `GameBootstrap.cs:45` — `LanternPositions` через `ConvertAll` создаёт новый список на каждый вызов. Сейчас проба используется только в тестах, в кадре её не вызывать.
- `architecture.md` → Test seams — нет строк для chain#R4 и chain#E3, хотя тесты есть. `Game.Presentation.asmdef` ссылается на `Game.Core`, а в `Depends on` у Presentation Core не указан (было и до diff).
- T-chain-09 (ED-chain-3, visual, P1) в diff отсутствует. Эталон и тест ещё не сделаны, либо живут вне diff.

## Что работает (коротко, механически)
- Генерация вынесена в чистый `ChainGenerator` без `MonoBehaviour`, как требует seam в `architecture.md`. Зависимости `Game.Chain` → Core, Hop совпадают с `Depends on`.
- Бросок искры передаётся в генератор callback'ом на том же `rng`, поэтому R5 воспроизводит и искры без зависимости Chain → Spark.
- Все четыре knob читаются из `ChainConfig`, значения ассета совпадают с GDD, тултипы ссылаются на ID.
- Сцена строит цепочку только через генератор (T-chain-08), старый дублирующий `AddNext` удалён.
- Подписка `chain.LanternAdded += Spawn` утечки не создаёт: при рестарте старый генератор выбрасывается целиком.
