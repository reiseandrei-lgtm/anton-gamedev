# gdd-review

## Принцип независимости
Ревьюер оценивает **только текст документа** (+ `pillars.md`, `concept.md`, `systems-map.md` как контекст). Не учитывает намерения из переписки. Не написано → не существует → finding.

## Режимы
- **single** — один GDD (по умолчанию).
- **cross** — все `design/gdd/*.md`: противоречия, устаревшие ссылки, формулы, конкуренция петель. Чек-лист: `references/cross-gdd.md`.

## Процедура (single)
1. Прочитай документ и контекст. Определи режим игры для весов (Mobile / PC / Multiplayer / Narrative) — `references/rubric.md`.
2. Проверь north star из `pillars.md` (если есть) и общие антипаттерны (`../gd-router/references/principles.md`).
3. Пройди 6 секций рубрики: Core Loop, Progression & Retention (Flow), Economy, Motivation (MDA, SDT, ludonarrative), Risk (Lake/Ocean, столпы), Cross-Consistency. Каждая — балл /10 с доказательством-цитатой.
4. Каждую проблему классифицируй: **AUTO** (очевидная правка: несоответствие имён, арифметика) · **ASK** (дизайнерский выбор пользователя) · **ESCALATE** (ревью не может продолжаться без решения).
5. Вопросы-вызовы из рубрики — не задавай интерактивно, а впиши в отчёт как «Вопросы автору» (макс. 5, самые острые).
6. Вердикт: PASS (взвешенный ≥7 и нет ESCALATE) · CONCERNS (5–7 или есть ASK с высоким риском) · FAIL (<5 или любой ESCALATE).

## Формат отчёта
`references/report-template.md`. Порядок (общий для всех ревью): **вердикт и главная проблема** (или нарушение north star) первым абзацем → что работает (механические причины) → что ломается, по тяжести, каждая находка **с альтернативой** → что делать (2–3 действия по эффект/стоимость).

## Тон
`references/anti-sycophancy.md`. Прямо, без комплиментов. Хорошее описывать только как механическую причину, почему это работает.

## Правила
Язык отчёта = язык запроса (или язык документа, если запрос нейтрален). Художественный текст не пишешь. Не выдумывай механики, которых нет в тексте.
