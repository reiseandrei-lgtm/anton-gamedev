## 1. Формат `design/levels/<level>.md`

Скрипт читает frontmatter и таблицы разделов `## Metrics`, `## Layout`, `## Encounters`, `## Pacing`, `## Gates` (по началу заголовка). Шаблон — `templates/design/levels/_template.md`.

```markdown
---
status: draft
updated: YYYY-MM-DD
owner:
level: opening
target_length: 1-1.5 min      # диапазон или число (±20 %)
start: N0                     # по умолчанию — первый From в Layout
goal: N9                      # по умолчанию — последний To
---

## Metrics
| ID | Metric | Kind | Move | Knob | Value |
|---|---|---|---|---|---|
| LM1 | максимальный прыжок | gap_max | hop | hop#K3 | 4.0 |

## Layout
| ID | From | To | Move | Gap | Height | Path | Dir |
|---|---|---|---|---|---|---|---|
| L1 | N0 | N1 | hop | 1.4 | 0 | critical | → |

## Encounters
| ID | Where | Uses | Wave | Trigger | Tension |
|---|---|---|---|---|---|
| EN1 | N4 | spark#R1 | — | приземление на N4 | 1 |

## Pacing
| Minute | Tension | Beat |
|---|---|---|
| 0:00 | 0 | teach L1 |

## Gates
| ID | Link | Key | Key at |
|---|---|---|---|
| G1 | L6 | key_red | N3 |
```

- **Metrics**: `Kind` — `gap_max` (зазор не больше), `gap_min` (не меньше), `height_max` (высота не больше); другие виды скрипт не проверяет. `Move` — тип движения (`hop`, `dash`, `*` — любой). `Knob` — `<system>#K<n>`; `Value` можно не писать — возьмётся `Current` из GDD. Своё число без knob — нельзя: метрика принадлежит системе.
- **Layout**: узлы — любые имена (`N0`, `arena_center`); `Gap` и `Height` — в единицах GDD, `—` если не применимо; `Path` — `critical` или `optional`; `Dir` — `→` (по умолчанию) или `↔`.
- **Encounters**: `Where` — узел или связь; `Uses` — через запятую `<system>`, `<system>#<ID>`, можно с множителем `×3`; `Wave` — номер волны на арене; `Tension` 0–3.
- **Pacing**: `Minute` — `м:сс` или дробь; последняя строка — конец уровня; `Tension` 0 (покой) … 3 (пик).
- **Gates**: `Link` — ID связи с замком; `Key` — что открывает; `Key at` — узел, где ключ берут. Ветка до ключа гейта на критическом пути — тоже `critical`: без неё цель не пройти.

## 2. Приёмы
- **Метрики первыми.** Все размеры — в единицах движения персонажа. Изменился knob → пересчитай уровень (`check_level.py` поймает).
- **Зазоры.** Обязательный прыжок ≈ 0.7 от `gap_max`; 0.9–0.95 — только необязательная награда. Ниже `gap_min` — тоже недостижимо, если прыжок не умеет «короче минимума».
- **Teach → practice → test → twist.** Новая механика: безопасное место (провал без наказания) → повтор → проверка под давлением → комбинация с прошлой.
- **Темп.** Пик (3) держится коротко, после него отдых (0–1): игрок осознаёт, что произошло. Два пика подряд без отдыха — усталость, а не сложность.
- **Встречи.** Каждая встреча отвечает на вопрос «чему учит или что проверяет». Волны арены: 1-я — знакомство, 2-я — комбинация, 3-я — давление; между волнами — окно на пополнение.
- **Гейты и навигация.** Замок — только с ключом на пути до него; ведут светом, линиями и ориентирами, а не стенами. Односторонний спуск тоже гейт: за ним должен быть выход.
- **Чекпоинты** — перед пиком, а не после: повтор начинается с напряжения, а не с прогулки.
- **Процедурные уровни.** Авторский участок (например, FTUE) — здесь; правила генератора — в GDD системы. Параметры генератора в Metrics — ссылками на knobs.

## 3. Проверки `check_level.py`
| ID | Что | Уровень |
|---|---|---|
| LV1 | зазор > `gap_max`, < `gap_min`, высота > `height_max` для этого `Move`; knob не найден; нет ни knob, ни Value | FAIL |
| LV1 | `Value` расходится с `Current` в GDD | WARN |
| LV2 | два пика (3) без отдыха (≤ 1) между ними; напряжение вне 0–3 | FAIL |
| LV3 | гейт на связи `critical` без ключа или узла ключа; ключ достижим только через свой гейт; `goal` недостижим от `start` | FAIL |
| LV4 | встреча: узел/связь не из Layout, система не найдена в `--gdd` / `--systems`, ID не найден в GDD | FAIL |
| LV5 | конец Pacing вне `target_length` (диапазон или ±20 %) | FAIL |

Пустая таблица Layout или Pacing — FAIL: уровень без пути или темпа не спроектирован.
