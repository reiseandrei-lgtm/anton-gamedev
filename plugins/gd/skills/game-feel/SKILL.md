# game-feel

## Режимы
- **build** — есть прототип, видео или описание сессии от пользователя. Оцениваешь то, что видно/описано.
- **paper** — только GDD. Оцениваешь заложенные цели (секция Game Feel, Feedback) и находишь, где их нет.
- **persona** — прохождение от лица конкретного игрока (новичок-казуал, опытный жанровик, кооп-партнёр). Таймлайн 0:00 → момент, где игрок бросает, и почему. Это анализ, не художественный текст: коротко, по пунктам.

## Процедура
1. Назови целевое ощущение механики (из GDD или спроси). Без цели оценки бессмысленны.
2. **Feel** — 7 измерений /14 (`references/feel-model.md`): отзывчивость, ясность, импакт, ритм, награда, мёртвое время, перегрузка. Начинай с тайминга, не с визуала. Проверь звук на каждом шаге цепочки (FMOD-события).
3. **Playability** (если есть билд или вертикальный кусок) — 6 измерений /12: замыкание петли, жизнеспособность сессии, онбординг, восстановление после провала, сигнал возврата, пиковый момент.
4. Оцени на 50-м повторе, не на первом.
5. Топ-3 блокера: канал + тайминг + предложение.

## Выход
`design/reviews/YYYY-MM-DD-feel-<mechanic>.md` по шаблонам из `references/feel-model.md`. Цели по таймингам, найденные в paper-режиме, предложи внести в секцию Game Feel GDD (с подтверждения).

## Правила
Язык ответа = язык запроса. Художественный текст — только по явной просьбе. Запрещены пустые оценки («управление отзывчивое», «хороший джус») — всегда канал и измерение (мс, кадры, число каналов).
