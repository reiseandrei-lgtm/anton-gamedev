# metrics-plan

Ты строишь минимальный набор событий, который отвечает на вопросы дизайна. Событие без вопроса — шум. Вопрос без порога решения — любопытство.

## Вход
`handoff/<slice>.md` (гипотеза), `ux/ftue.md` (шаги и события), `balance/*.md` (проекции D1 / D7 / D30), `playtest/*.plan.md` (пороги), `pillars.md` (north star).

## Алгоритм (формат, нейминг, якоря — `references/metrics-method.md`)
1. **Вопросы**: из гипотез, FTUE и баланса. Каждый вопрос → KPI → порог решения («если < X, то …»).
2. **События**: минимальный набор, из которого считаются все KPI. Нейминг `object_action` в `snake_case`, прошедшее время действия (`level_completed`). Параметры — только нужные для KPI.
3. **Воронки**: FTUE (шаги из `ux/ftue.md`), core loop, первая сессия. Шаг = событие, ожидаемая конверсия и порог тревоги.
4. **Retention и сессии**: D1 / D7 / D30, длина сессии, сессий в день — цели ГИПОТЕЗА с якорем (жанр, платформа, прошлый проект) и сигналом пересмотра.
5. **Приватность**: без PII; идентификатор — анонимный install id; согласие по правилам платформы и региона.
6. **Реализация**: вендор-агностично. Бесплатные варианты — в references; платные SDK не предлагать.

## Проверка
`python3 scripts/check_events.py design/analytics/events.md [--funnels design/analytics/funnels.md]`: M1 нейминг события или параметра · M2 дубль · M3 шаг воронки без события · M4 KPI ссылается на несуществующее событие · M5 параметр с признаками PII · M6 событие без связи с вопросом или KPI (WARN) · M7 KPI без порога решения. На Windows — `python`.

## Done
Скрипт без FAIL; у каждой гипотезы слайса есть KPI, событие и порог; воронка FTUE совпадает с шагами `ux/ftue.md`.

## Правила
Язык ответа = язык запроса. Числа-цели — ГИПОТЕЗА с якорем (`../gd-router/references/principles.md`). Метрика не заменяет плейтест: на 5 игроках D7 не посчитать — для слайса главное воронки и время до шагов. Художественный текст не нужен.
