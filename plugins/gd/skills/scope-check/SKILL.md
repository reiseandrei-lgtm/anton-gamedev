# scope-check

## Вход
`design/systems-map.md`, MVP-GDD, `design/scope.md` (прошлый baseline, если есть), ресурсы команды (спроси, если не указаны: люди × часы/неделю × недели до цели).

## Процедура
1. **Инвентарь контента.** Конечный список: системы, уровни/локации, персонажи, карты/предметы, сцены, ассеты, звук, UI-экраны. Любое «и т.д.», «процедурно», «бесконечно» = Ocean → потребуй минимальный набор.
2. **Оценка.** По каждому пункту: S/M/L/XL → человеко-дни по `references/estimation.md`, уверенность (высокая/средняя/низкая), риск-множитель для недоказанной технологии.
3. **Сравнение.** Сумма × 1.2 (буфер) против ресурсов. Если есть baseline — scope creep % и вердикт.
4. **Классификация.** Must (без этого core loop / столп не работает) · Should · Cut. Для каждого cut: что ломается без него.
5. **Порядок вырезания** — от наименьшего ущерба столпам к наибольшему. Вопрос-проверка: «Что вырежешь, если выпускать на 3 месяца раньше?»

## Выход
`design/scope.md` по шаблону: ресурсы · инвентарь с оценками · итог vs ресурсы · вердикт · must/should/cut · порядок вырезания · риски. Решения о вырезании — только пользователь; фиксировать в `decisions-log.md` и обновить приоритеты в `systems-map.md` (с подтверждения).

## Правила
Язык ответа = язык запроса. Всегда количественно: не «кажется большим», а «+35% пунктов, 140 чел-дней при 90 доступных». Сохраняй core-опыт, режь nice-to-have.
