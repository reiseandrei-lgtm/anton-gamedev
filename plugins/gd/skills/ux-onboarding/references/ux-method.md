# UX и онбординг: шаблоны и чеклист

> Пороги тач-целей и текста — из gstack-game `game-visual-qa/visual-thresholds` (MIT © 2026 fagemx), см. ATTRIBUTION.md. Остальное своё: методы show/do/gate/defer, формат, связь с метриками и плейтестом. Чеклист доступности — пересказ публичных Game Accessibility Guidelines (gameaccessibilityguidelines.com), уровень Basic.

## 1. ftue.md

```markdown
---
status: draft
updated: YYYY-MM-DD
owner:
target_first_action_s: 60
target_loop_closed_min: 3
---
# FTUE — <Game>

## What the player must learn
| ID | Понимание | Зависит от | Метод | Минута | Проверка (DD / плейтест) | Событие метрики |
|---|---|---|---|---|---|---|
| L1 | тап = прыжок | — | do | 0:05 | DD1 | ftue_first_jump |

## First session timeline
| Время | Что видит | Что делает | Что понимает (L) | Риск ухода |
|---|---|---|---|---|

## Failure handling
Первый провал: что игрок видит, как понимает причину, сколько секунд до повтора.

## Deferred
Что сознательно не учим в первой сессии и когда научим.
```

Правила: одно новое понимание за раз · действие раньше текста · первый провал бесплатный и объяснённый · туториал можно пропустить повторно играющему · нет «стены текста» (> 2 строк подряд).

## 2. hud.md

```markdown
## Information inventory
| Info | Источник (GDD) | Нужна | Приоритет | Частота | Зона | Форма | Name | Loc key |
|---|---|---|---|---|---|---|---|---|
| счёт | jump#K2 | always | 2 | на событие | top-center | число | hud-score | — |

- **Name** — имя элемента в UXML (`name="hud-score"`), по нему `gd-build: ui-build` проверяет, что элемент реализован. Диегетика (не UI) — `—`.
- **Loc key** — ключ локализации строки элемента (`ui.again`); число или иконка — `—`. Колонки общие с `ui-build` и `loc-build`: меняешь — меняй там.
```

- **Нужна**: `always` · `contextual` (появляется по событию) · `on-demand` (по запросу / меню).
- **Приоритет**: 1 — от неё зависит решение прямо сейчас; 2 — прогресс; 3 — справка.
- **Зона (мобайл, портрет)**: нижняя треть — большие пальцы, туда управление, не информация priority 1; верх — статус; центр — игровое поле, только contextual. Учитывать safe area (вырез, жесты).
- **PC**: углы для статуса, центр — прицел и contextual.

## 3. Чеклист доступности (базовый уровень)

| # | Пункт | Как проверить |
|---|---|---|
| A1 | Громкость по шинам: музыка, SFX, голос отдельно | меню настроек |
| A2 | Субтитры для всей речи, с именем говорящего; размер субтитров настраивается | меню, скриншот |
| A3 | Информация не передаётся только цветом | `check_palette.py` + форма или иконка |
| A4 | Информация не передаётся только звуком | визуальный дубль critical-звуков |
| A5 | Текст ≥ минимума платформы, масштаб UI настраивается | пороги в `art-direction/references/art-method.md` §3 |
| A6 | Удержание можно заменить переключением (hold → toggle) | настройки ввода |
| A7 | Пауза в любой момент (кроме онлайна — записать) | плейтест |
| A8 | Управление переназначается (PC) / тач-цели ≥ 44 pt / 48 dp (мобайл) | меню / замер |
| A9 | Нет быстрых вспышек 3+ раз в секунду; есть опция снизить тряску и вспышки | видео 60 fps, покадрово |
| A10 | Сложность или помощь регулируются без стыда (не «режим для слабых») | меню |
| A11 | Туториал и подсказки можно повторить | меню |
| A12 | Однорукая игра возможна (мобайл) или записано, почему нет | плейтест |

Статус: `pass` · `gap` · `n/a` (с причиной). `gap` без решения — нарушение Done.

## 4. Частые ошибки
Учим всё сразу · текст вместо действия · провал без причины · priority-1 информация под пальцем · HUD из десятка чисел в mechanic-слайсе · доступность «потом» (в конце её не добавить дёшево).
