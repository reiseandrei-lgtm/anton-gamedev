## 1. Авторство (жёсткое правило)
| Пишет человек 🟨 | Пишет скилл |
|---|---|
| короткое и длинное описание, заголовки, подписи, alt-тексты, CTA; письма, пресс-релиз, посты, анонсы; подписи и титры трейлера, озвучка; капсула и ключевой арт | план, таблицы, чеклист, находки аудита, вопросы автору, бриф для художника, go / no-go |

Текста нет → вопросы, которые вытянут слова автора («что игрок делает раз за разом?», «чем кончается забег?»), ответ цитируется дословно. Замечания к тексту — ошибка факта, неподтверждённое обещание, нарушение правил платформы, двусмысленность — с просьбой переписать самому. Машинный перевод утверждённого исходного текста допустим с отметкой «нужна проверка носителем».

## 2. Формат

Скрипт читает все таблицы трёх файлов по заголовкам колонок.

**store.md** — `## Assets`: `ID · Asset · Kind · Author · Status · Notes`. `Kind`: `text`, `capsule`, `key-art`, `screenshot`, `trailer`, `tags`, `other`. `Author`: `human` или источник (`qa-run` для скриншотов). `Status`: `todo`, `human`, `approved`. `## Tags`: `# · Tag · Why · Comparable`. `## Audit`: `ID · Finding · Severity · Evidence · Owner` (`blocker / high / improvement / verified`). Frontmatter: `store`, `rules_checked: YYYY-MM-DD`.

**launch.md** — `## Milestones`: `ID · Milestone · Kind · Date · Status`, `Kind`: `page`, `demo`, `fest`, `release` (прочие — `other`, порядок не проверяется). `## Checklist`: `ID · Item · Dept · Owner · Due · Status` (+ `Kind` и `Author`, если пункт — текст для игроков). `Due`: `YYYY-MM-DD` или `R-14` (дней до релиза). `## Go / No-go`: `Criterion · Source · Verdict`.

**postlaunch.md** — `## Metrics`: `Metric · Source · Threshold · Action · Addressee`. `## Patches`: `Type · Trigger · Path · Owner`. `## Rollback`: как вернуть прошлую сборку (ветка Steam, тег).

Шаблоны — `templates/design/release/`.

## 3. store — аудит в порядке покупателя
1. **Капсула** — жанр читается в маленьком размере, название разборчиво, арт человека.
2. **Трейлер** — геймплей в первые секунды; беззвучный цикл превью понятен; титры и озвучка — человек.
3. **Скриншоты** — первые 4–5 показывают игру, а не меню; актуальный билд; разнообразие ситуаций.
4. **Короткое описание** — жанр и глагол игрока; только авторские слова.
5. **Теги** — упорядочены от самого определяющего; каждый с доказательством из игры и 2–3 сравнимыми играми, чьи игроки — наша аудитория; без тегов «для охвата».
6. **Остальное** — языки (галочка «Интерфейс» / «Субтитры» только при реальной локализации в игре — `loc-build`), платформы, системные требования из `qa/perf`, раскрытие контента, живые ссылки.

## 4. launch — вехи и чеклист
- **Вехи**: страница (coming soon) → демо (у демо на Steam должна быть страница основной игры) → фест (нужны страница и демо) → релиз. Демо на itch.io до страницы Steam — веха `other` (плейтест), не `demo`. Между вехами — запас на ревью платформы; сроки ревью — из текущей документации.
- **Отделы чеклиста**: код (RC из тега, 0 S1 / S2, откат), контент (`scope.md` закрыт, `check_import.py` без `ph_`), магазин (store.md без `blocker`), маркетинг (анонс даты, пресс-кит — тексты человека), сообщество (канал поддержки, known issues), инфраструктура (краш-репорты, аналитика — `analytics-build`), юридическое (политика конфиденциальности, возрастной рейтинг, лицензии из `ATTRIBUTION` и `audio/files.md`).
- **Go / No-go**: каждый критерий ссылается на файл (`qa/runs/<date>.md` PASS, `qa/perf/<date>.md` PASS, `release/builds.md` строка RC). Нет файла — `no-go`, а не «вроде готово».

## 5. postlaunch
- Метрики — KPI из `analytics/events.md` / `funnels.md`: порог решения, действие (`iterate` / patch / hotfix) и адресат (`ux-onboarding`, `balance-check`, `game-feel`, `feature-build` …). Метрика ниже порога → стадия 12 роутера.
- Патчи: **hotfix** — S1 (игра не запускается, потеря сохранений): `feature-build` → `qa-run` → `build-release` из ветки `hotfix/*`, откат готов до выкладки; **patch** — S2 и накопленные S3 по расписанию; **day-one** — то, что не успело в RC, собирается и тестируется как обычный патч.
- Первые 72 часа: блокеры покупки, запуска, сохранения, управления, прохождения — в приоритете; отчёты старого билда отделять от текущего.
- Отзывы: не стимулировать, не просить в игре, не спорить; короткий фактический ответ — только если дефект исправлен.

## 6. Проверки `check_release_plan.py`
| ID | Что | Уровень |
|---|---|---|
| RP1 | строка `## Checklist` без `Owner` или `Due` (дата `YYYY-MM-DD` или `R-n`) | FAIL |
| RP2 | вехи `page → demo → fest → release` вне порядка | FAIL |
| RP2 | у вехи нет даты | WARN |
| RP3 | строка с `Kind` ∈ `text`, `capsule`, `key-art`, `post`, `email` без `Author: human` | FAIL |
| RP4 | строка `## Metrics` без `Threshold` или `Addressee` | FAIL |
| RP4 | метрики нет среди KPI `--events` | WARN |
