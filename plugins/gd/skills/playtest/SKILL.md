# playtest

Ты превращаешь «дай поиграть друзьям» в эксперимент с заранее заданным порогом, а заметки — в решения с адресатами.

## Режим plan → `design/playtest/YYYY-MM-DD-<slice>.plan.md`
Вход: `handoff/<slice>.md` (гипотеза, DD), `ux/ftue.md`, `qa/test-plan-<slice>.md` (playtest-кейсы), последний `qa/runs/*` (нет S1/S2).
1. Гипотеза из хендоффа: «если X, то игрок Y за Z». Размыта → заостри вместе с пользователем.
2. ≤ 3 вопроса исследования. Каждый — к DD или playtest-кейсу.
3. **Порог до сессий**: при каком наблюдении гипотеза `confirmed` / `refuted` (например, «≥ 4 из 5 делают X без подсказки за 60 с»). После сессий порог не меняется.
4. Участники: 5 на раунд (соло-разработчик — от 3); свои и чужие — разные сегменты.
5. Задачи без подсказок, длительность, стартовая точка, одна и та же сборка у всех.
6. Скрипт наблюдения с кодами и таймкодами; правила наблюдателя; вмешательство только после 2 минут полного тупика.
7. Опросник и интервью по `references/playtest-method.md`; наводящие вопросы запрещены.
8. Метрики для сессии (если есть телеметрия) — из `analytics/events.md`.

## Режим analyze → `design/playtest/YYYY-MM-DD-<slice>.report.md`
Независимый анализ делает агент `playtest-analyst` (`/gd:playtest analyze`): он видит только заметки, опросники и `.plan.md`, но не GDD и не намерения автора.
1. Нормализуй заметки в формат `[mm:ss] CODE текст` (по файлу на игрока или `## P<n>`).
2. `python3 scripts/aggregate_codes.py design/playtest/<date>-<slice>/notes/*.md` — частоты кодов по игрокам, «горячие» окна (≥ 50 % игроков с C / F / S в одном окне), первые провалы. На Windows — `python`.
3. Находки: частота (сколько игроков) × тяжесть (P0–P3) по матрице из references. Нужно минимум 2 источника из трёх: наблюдение, метрика, слова игрока. Один источник — гипотеза, не находка.
4. Вердикт `confirmed / refuted / inconclusive` строго по порогу из плана.
5. У каждой находки адресат: `game-feel` · `balance-check` · `gdd-author --quick` · `ux-onboarding` · `art-direction` · `audio-direction` · баг `qa/bugs`.
6. Предложение строки для `decisions-log.md` (iterate / pivot / kill / advance). Решает пользователь.

## Done
plan: порог записан, опросник без наводящих, задачи без подсказок. analyze: вердикт по порогу, топ-находки с частотой, тяжестью и адресатом, предложение для decisions-log.

## Правила
Язык ответа = язык запроса. Цитаты игроков — дословно, в кавычках, как данные. Не объясняй провал «игрок не понял» без механической причины. Не подгоняй порог после сессий. Художественный текст не нужен. Платные сервисы рекрутинга и записи не предлагать: запись экрана — встроенная запись ОС или OBS.
