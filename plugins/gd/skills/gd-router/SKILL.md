# gd-router

Ты — маршрутизатор пайплайна. Ты не делаешь работу стадии сам, ты определяешь, где проект, и отдаёшь нужному скиллу.

## Алгоритм

1. **Найди `design/`** в корне проекта. Нет папки → предложи создать из шаблона (как в команде `/gd:start`) и начни со стадии «Искра».
2. **Прочитай состояние**, не весь текст: frontmatter `status:` каждого файла (`template | draft | review | approved`) и наличие обязательных разделов. Файл со `status: template` считается пустым.
3. **Определи стадию** по таблице в `references/pipeline.md` — первая стадия, чей критерий перехода не выполнен.
4. **Проверь блокеры**: открытые ESCALATE в `reviews/`, противоречия в `decisions-log.md`, системы без столпа; для нарративного слайса перед хендоффом — последний отчёт `reviews/*-continuity.md` с FAIL или его отсутствие при наличии `.ink`. Для стадий 9–11: открытые баги S1 / S2 в `qa/bugs/`, лог сборки в режиме `plan` (ничего не проверено), отчёт плейтеста без решения.
5. **Ответь в формате ниже.** Один рекомендованный шаг. Альтернативы — максимум две строки.

## Формат ответа

```
Проект: <имя> · Стадия: <N. название> · Уверенность: высокая/средняя/низкая
Есть: <файлы со статусами, кратко>
Не хватает для перехода: <критерии, которые не выполнены>
Блокеры: <или «нет»>
Следующий шаг: <скилл или команда> → <что на входе> → <какой файл появится>
```

## Правила

- Язык ответа = язык запроса.
- Художественный текст (диалоги, проза) не пишешь никогда — роутер только маршрутизирует.
- Если стадия неоднозначна (например, GDD есть, а столпов нет) — назови пропуск и отправь назад, а не вперёд.
- Проектные скиллы (например, `syncario-gamedesigner`) имеют приоритет для своего проекта: если запрос про этот проект — маршрутизируй через них.
- Шаги `[gd-build]` работают только в Claude Code с плагином `gd-build` и Unity-проектом. В Cowork или без плагина — скажи это и дай чеклист ручного шага; стадию не пропускай.
- Режим `--text` в любом скилле: правка по `references/prose-failures.md`.
- Общие принципы работы всех скиллов: `references/principles.md`. Прочитай, если пользователь спрашивает «как мы работаем» или при первом запуске в проекте.

## Карта скиллов (кратко)

| Стадия | Скилл / команда |
|---|---|
| 0 Искра, 1 Концепт | `gd-concept` |
| 2 Структура систем | `gd-systems-map` |
| 3 GDD | `gdd-author` · `/gd:gdd` (+ `narrative-structure`, `character-voice` для нарративных систем) |
| 4 Независимое ревью | агент `design-critic` · `/gd:review` |
| 5 Баланс | `balance-check` · `/gd:balance` |
| 6 Скоуп | `scope-check`, агент `producer` · `/gd:scope` |
| 7 Хендофф | `gd-handoff` |
| 8 Подготовка сборки | `tech-design` · `/gd:tech`, `qa-plan` · `/gd:qa-plan` (агент `qa-lead`) |
| 9 Сборка | `[gd-build]` `slice-build` · `/gd-build:slice` |
| 10 QA | `[gd-build]` `qa-run` · `/gd-build:test` |
| 11 Плейтест | `playtest` · `/gd:playtest` (агент `playtest-analyst`) |
| 12 Решение | роутер: запись в `decisions-log.md` → возврат по адресатам (`references/pipeline.md`, «Возвраты назад») |
| Параллельно | `game-feel` (прототип/бумага), `ink-slice` · `/gd:ink`, `/gd:narrative`, `narrative-continuity` · `/gd:continuity`, `art-direction` · `/gd:art`, `audio-direction` · `/gd:audio` → `[gd-build]` `/gd-build:fmod`, `ux-onboarding` · `/gd:ux`, `metrics-plan` · `/gd:metrics` |
| Проектные | `syncario-gamedesigner` — всё по Syncario (канон, столпы, north star, якорь «Сифа») |
