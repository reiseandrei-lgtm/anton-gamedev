# narrative-structure

## Вход
`design/pillars.md`, `design/concept.md`, `design/narrative/world.md`, существующие `branches/`, GDD нарративных систем (диалоги, квесты, отношения).

## Задачи (определи по запросу)
- **Мир** — правила мира (что возможно/невозможно), история, фракции, связи, релевантность для игрока. `references/narrative-models.md` → World.
- **Ветка / сцена** — консеквенс-дерево: точка выбора → что знает игрок → варианты → немедленное последствие → отложенное последствие → куда сходится. Тип структуры (branch-and-bottleneck, hub-and-spoke, parallel paths, state-driven/storylets, open quest).
- **Критический путь** — игра проходима минимум одним понятным маршрутом без жёсткого порядка; критическое знание не пропускается без альтернативы.
- **Continuity** — поиск противоречий фактов, таймлайна, состояния между документами. Неоднозначное помечай как неоднозначное, не «исправляй» уверенно.
- **Ludonarrative** — 4 теста (тема↔механика, тон↔ощущение, персонаж↔способности, мир↔системы). Намеренный диссонанс записать в `decisions-log.md`.

## Процедура
1. Задавай вопросы о решениях (что должна чувствовать развилка? какое последствие игрок заметит?), не решай за автора.
2. Каждое последствие — изменение состояния (переменная/флаг/отношение) с именем на английском.
3. Проверь: выборы без последствий (ложный выбор — ок только если намеренный), комбинаторный взрыв (>3 уровней ветвления без схождения), недостижимые ветки, сироты-флаги.
4. Покажи структуру (таблица / mermaid), затем запиши.

## Выход
`design/narrative/world.md`, `design/narrative/branches/<branch>.md` по шаблонам из `references/narrative-models.md`. Новые переменные состояния → список «State» в файле ветки.

## Правила
Язык ответа = язык запроса. **Прозу, диалоги, описания, лор-тексты не писать без явной просьбы** — только биты в формате «[БИТ: что происходит, что узнаёт игрок, эмоция]». Без воды.
