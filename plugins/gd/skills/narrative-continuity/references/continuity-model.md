# Модель континуити

## Что считается промисом
Всё, что создаёт у игрока ожидание: вопрос без ответа, тайна, запертая дверь, упомянутый предмет, угроза, обещание персонажа, намёк на прошлое, умение/предмет, выданное «на потом».
Промис окупается (paid), когда ожидание разрешено: ответ, использование, раскрытие, осознанный обман ожидания. Сознательный отказ от пэйоффа = `dropped` + строка в decisions-log.

## Типы ошибок
| Код | Что | Уровень |
|---|---|---|
| C1 missing-node | setup/payoff ссылается на несуществующий узел | FAIL |
| C2 unreachable | пэйофф не достижим из сетапа ни по одному пути | FAIL |
| C3 bypass | до пэйоффа можно дойти, минуя сетап | WARN (FAIL, если пэйофф без сетапа непонятен) |
| C4 unfired | `open` без пэйоффа | WARN; FAIL на стадии хендоффа, если нет решения |
| C5 knowledge-leak | сцена опирается на знание, которого нет в этой ветке | FAIL |
| C6 presence | персонаж действует после ухода/смерти/в другом месте | FAIL |
| C7 canon | противоречие строке canon.md со статусом ФАКТ | FAIL |
| C8 partial-payoff | пэйофф есть только в части веток | INFO; записать ветки |

## Узлы слияния
Знание игрока в узле слияния = пересечение знаний всех входящих веток. Если реплика после слияния предполагает знание из одной ветки — нужен условный вариант (`{flag: … | …}`) или перенос. Это самая частая ошибка ветвящихся игр.

## Шаблоны

### promises.md
```
---
status: draft
updated: YYYY-MM-DD
owner: <автор>
---
# Промисы

| id | setup | payoff | status | note |
|---|---|---|---|---|
| P01 | camp.arrival | lake.night_swim | open | фото утонувшей вожатой на стенде |
```

### state.md
```
---
status: draft
updated: YYYY-MM-DD
owner: <автор>
---
# Состояние по узлам

## <узел>
- Игрок знает: …
- <персонаж> знает: … · где: … · статус: жив/ушёл
- Флаги/предметы: …
```

### canon.md
```
---
status: draft
updated: YYYY-MM-DD
owner: <автор>
---
# Канон

|---|---|---|---|
| K01 | Лагерь закрыли в 1987 | world.md | ФАКТ |
```
