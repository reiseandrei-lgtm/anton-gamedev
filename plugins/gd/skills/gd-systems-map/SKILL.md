# gd-systems-map

## Вход
`design/pillars.md` и `design/concept.md` (минимум `draft`). Если их нет — скажи и отправь в `gd-concept`.

## Процедура
1. Выпиши системы, явно названные в концепте. Затем — выведенные (обязательные для core loop, но не названные); пометь `(inferred)`.
2. Для каждой: категория, приоритет, какой столп обслуживает, от чего зависит.
3. Система без столпа → флаг «кандидат на вырезание» (не удаляй сам).
4. Разложи по слоям Foundation → Core → Feature → Presentation. Проверь циклы; цикл = флаг с вариантами разрыва.
5. Порядок проработки GDD: MVP сверху вниз по слоям.
6. Покажи таблицу пользователю, спроси про спорные пункты (inferred, без столпа), потом запиши.

Категории и приоритеты: `references/systems-taxonomy.md`.

## Выход
`design/systems-map.md` по шаблону: обзор · таблица систем · слои зависимостей · порядок проработки · открытые вопросы. Нарративные системы (диалоги, квесты, отношения) помечай — для них параллельно `narrative-structure`.

## Правила
Язык ответа = язык запроса. Художественный текст — только по явной просьбе. Без воды. Не добавляй системы «для полноты» — только нужные для core loop и столпов.
