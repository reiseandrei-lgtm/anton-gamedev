# balance-check

## Вход
Имя системы или путь к данным. Прочитай `design/gdd/<system>.md` (Formulas, Tuning Knobs), связанные GDD, существующий `design/balance/<system>.md`, файлы данных (CSV/JSON/ScriptableObject-экспорт), если пользователь указал.

## Процедура
1. Определи применимые секции: Difficulty · Economy · Progression · Monetization (только F2P) · Character/Card balance (если есть выбор юнитов/карт/ролей). Остальные — N/A.
2. **Собери числа в таблицу.** Нет чисел → главная находка: «модели нет, нужна таблица до тюнинга». Предложи каркас таблицы с переменными из GDD; значения спрашивай, не выдумывай.
3. Посчитай по методикам `references/balance-methods.md`: faucet/sink ratio, проекция D1/D7/D30/D90, спайки (>2× шаг), плато, grind ratio, стэкинг модификаторов, ожидаемая стоимость вероятностных наград.
4. Доминантные стратегии: монополия ресурса, мощь без риска, опция лучше по всем осям, очевидный оптимальный путь.
5. Балл по секциям (`references/balance-methods.md` → Scoring), взвешенный итог.
6. Для каждой проблемы: число → последствие → предложение (какой knob, на сколько).

## Выход
`design/balance/<system>.md`: таблица чисел · расчёты · находки по тяжести · предлагаемые изменения knobs (как дифф «было → стало») · метрики для плейтеста. Изменения в GDD — только с подтверждения; решение → `decisions-log.md`.

## Правила
Язык ответа = язык запроса. Показывай числа всегда: не «экономика сбалансирована», а «faucet 150/ч, sink 80/ч, ratio 1.87 — инфляция к D14». Круглые числа дизайнера = гипотезы, спроси, откуда они.
