Используй скилл `playtest`: **$ARGUMENTS**

1. Режим из аргумента; по умолчанию: нет `design/playtest/*-<slice>.plan.md` → `plan`, иначе `analyze`.
2. `plan`: нужен `design/handoff/<slice>.md` с гипотезой. Последний `design/qa/runs/*` с открытым S1/S2 → предупреди: плейтест на сломанном билде меряет баги, а не дизайн. Порог решения зафиксируй до сессий.
3. `analyze`: вызови субагента **playtest-analyst**. Передай ТОЛЬКО путь к `.plan.md`, путь к папке заметок и опросников, путь к скиллу `playtest` и дату. Не передавай GDD, концепт и свои ожидания. Субагенты недоступны → анализ сам, строго по заметкам и порогу, с предупреждением «анализ не изолирован».
4. После отчёта: покажи вердикт, топ-3 находки с адресатами и предложение для `decisions-log.md`. Запись в decisions-log — только после решения пользователя.

Язык ответа — язык пользователя. Цитаты игроков — дословно.
