# analytics-build: генерация, вызовы, JSONL, согласие

Свой документ. Принципы событий — `gd:metrics-plan` (`metrics-plan/references/metrics-method.md` в плагине `gd`); схема «константы из дизайн-документа + проверка строк в коде» — как у `fmod-sync`.

## 1. Генерация
`gen_analytics.py events.md --out <папка> [--namespace Game.Analytics] [--no-backend]`:
- `AnalyticsEvents.cs` — `Names.<Event>` (строка `object_action`) и метод на событие: `AnalyticsEvents.JumpPerformed(int jumpIndex, float charge, …)`. Типы: `int`, `float`, `bool`, `string`; `enum[a/b]` → `string` (допустимые значения — в XML-комментарии).
- `AnalyticsLog.cs` — локальный бэкенд: `Application.persistentDataPath/analytics/<session>.jsonl`, одна строка — одно событие: `{"ts":"<UTC ISO>","t":<сек от старта>,"session":"<guid>","event":"<имя>","params":{…}}`. `Consent = false` по умолчанию: без согласия событие отбрасывается. Ошибка записи — предупреждение в консоль, игра не падает. `Written` — событие для тестов.
- `--no-backend` — только `AnalyticsEvents.cs`, если бэкенд уже заменён по ADR (тогда `AnalyticsLog.Send` реализует адаптер).
- Файлы помечены `<auto-generated>`; правка events.md → перегенерация, не правка руками.

## 2. Вызовы
- Точка вызова — колонка Trigger: подписка на событие системы (`machine.Jumped += …`) или место смены состояния. Не опрос в `Update`.
- Параметры считаются из состояния систем в момент события; время — `Time.realtimeSinceStartup` или счётчики системы, не `DateTime.Now`.
- Один вызов — одно событие; в цикле или каждый кадр — только если так записано в events.md (обычно ошибка).
- Модуль аналитики зависит от систем, системы от аналитики — нет: вызовы в слое представления или в подписчике (`architecture.md`).

## 3. Согласие и приватность
- Плейтест: согласие в анкете до сессии → флаг сборки выставляет `Consent = true` на старте. Релиз: экран согласия (текст — человек), выбор сохраняется.
- Запрещено в параметрах: email, имена, телефон, адрес, IP, device id, рекламные id, свободный текст игрока (AN3 — те же правила, что `check_events.py`).
- Файл JSONL лежит на устройстве; забирает его человек (плейтест) — путь в логе сборки.

## 4. Тесты (EditMode, по тест-плану)
- С `Consent = true` вызов метода → одна строка в `Written`, имя = `Names.<Event>`, параметры с нужными ключами и типами.
- С `Consent = false` → ни одной строки.
- Числа в JSON — с точкой при любой культуре (`CultureInfo.InvariantCulture`).

## 5. Проверки `check_analytics_calls.py`
| ID | Что | Уровень |
|---|---|---|
| AN1 | событие events.md без вызова `AnalyticsEvents.<Event>(…)` / `Names.<Event>` вне сгенерированных файлов; `AnalyticsEvents.cs` расходится с events.md | FAIL |
| AN2 | строковый литерал с именем события или `AnalyticsLog.Send("…")` вне `AnalyticsEvents.cs` | FAIL |
| AN3 | параметр events.md или ключ в `("key", value)` вызова похож на персональные данные | FAIL |
| AN4 | вызовы есть, а присваивания `Consent` нет; бэкенд не проверяет `Consent` | WARN |
Тесты (`using NUnit.Framework`), `Library/`, `Packages/`, `Plugins/` пропускаются.
