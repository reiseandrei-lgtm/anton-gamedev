# Ревью кода системы: чеклист для агента code-reviewer

> Адаптировано из gstack-game `gameplay-implementation-review` (Pass 0 «Design Intent Survival», `pass1-critical.md`, `pass2-informational.md`; MIT © 2026 fagemx). См. ATTRIBUTION.md. Убраны bash-преамбула, телеметрия, авто-исправления и сетевые разделы для синглплеера; привязка к ID GDD, Config map и формат отчёта — свои.

Ревьюер видит только: diff, GDD системы, `tech/architecture.md`, тест-план. Он не исправляет код: он пишет находки с альтернативой.

## Pass 0. Сохранилось ли намерение дизайна (главное)
| Проверка | Как | Находка, если |
|---|---|---|
| 0.1 Каждое R / E системы | найти в diff место, где правило исполняется, и тест, который его проверяет | правила нет в коде или нет теста (FAIL, если правило P1 в тест-плане) |
| 0.2 Формулы F | выражение в коде = формула GDD, клампы и диапазоны совпадают | расхождение формулы (FAIL) |
| 0.3 Knobs K | каждое число из Tuning Knobs берётся из конфига по Config map | литерал-knob в коде (FAIL) |
| 0.4 «Душа» (Game Feel GDD) | то, что GDD называет душой механики, защищено тестом или конфигом | не защищено — CONCERNS |
| 0.5 Границы | diff не делает того, чего нет в GDD (новые правила, «улучшения») | тихое изменение опыта (CONCERNS) |

## Pass 1. Критичное
- **Кадр**: аллокации в `Update` / `FixedUpdate` / `LateUpdate` (`new`, LINQ, конкатенация строк, лямбды с захватом) каждый кадр; `Find*` / `GetComponent` в цикле кадра; расчёт по кадрам без `Time.deltaTime`.
- **Ресурсы**: подписка на событие без отписки (`OnDisable` / `OnDestroy`); `Instantiate` без пула в частом событии; загрузка без выгрузки.
- **Сохранения**: нет поля версии; поле переименовано или удалено без миграции; ошибка записи роняет игру (сравни с edge case GDD).
- **Ввод**: ввод не через Input System; чтение ввода и применение в разных фазах с лишним кадром задержки; жёстко зашитые клавиши без действия (Action).
- **Архитектура**: модуль зависит от модуля, которого нет в его `Depends on` (`architecture.md`); логика правил внутри `MonoBehaviour` там, где seam требует чистого класса.
- **Секреты**: ключи, токены, пути пользователя в коде.

## Pass 2. Информационное
- Магические числа, не являющиеся knobs (кандидат в knob — вопрос дизайнеру).
- UI меняет состояние игры напрямую вместо события.
- Тест проверяет реализацию, а не правило (повторяет выражение из кода).
- Мёртвый код, TODO без владельца, дубли логики.

## Вердикт
- **FAIL** — хоть одна находка FAIL в Pass 0 или Pass 1 (правило без кода или теста, формула расходится, knob литералом, утечка подписок в каждом кадре, сохранение без версии).
- **CONCERNS** — только CONCERNS и Pass 2.
- **PASS** — находок уровня CONCERNS и выше нет.
