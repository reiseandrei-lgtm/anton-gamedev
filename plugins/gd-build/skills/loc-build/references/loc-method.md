# loc-build: CSV, лимиты, псевдолокаль, импорт

Свой документ. Режимы scan / extract / validate — идея CCGS `localize` (MIT), текст свой. Unity Localization (`com.unity.localization`, Unity Companion License) используется как пакет: код и документация не копируются, API — по официальному Unity Plugin и документации пакета.

## 1. Таблица `design/loc/<Table>.csv`
Один CSV — одна String Table Collection (`UI.csv` → коллекция `UI`). Формат — как у расширения CSV пакета, чтобы импорт шёл без преобразований:

```csv
Key,Shared Comments,English(en),Russian(ru),Russian(ru) Comments
ui.again,max:8 · кнопка «ещё» на экране рестарта,Again,Ещё,
ui.record,max:12 · подпись над числом рекорда,Best,Рекорд,mt
```
- **Key** — `<префикс>.<имя>` в `snake_case` через точки; префикс = назначение (`ui`, `hint`, `ink_<slice>`), для Ink — ID из `#id:`.
- **Shared Comments** — `max:N` (символов на экране) и контекст для переводчика: где стоит, что рядом, род и число.
- **Колонки языков** — `<Имя>(<код>)`; первый язык — исходный (или `--source`). `<Имя>(<код>) Comments` — `mt` для машинного перевода до проверки носителем.
- Числа и имена — плейсхолдеры `{0}` / `{name}` (Smart Strings), не склейка. Род и множественное — отдельные ключи или Smart-формат, одинаковые плейсхолдеры во всех языках.
- Точные имена колонок расширения CSV сверить при первом live-импорте (экспорт пустой коллекции → сравнить заголовки); скрипт узнаёт язык по `(<код>)` в конце заголовка.

## 2. Лимиты
- Источник `max:N`: зона и форма в `ux/hud.md` (кнопка 48 dp ≈ 8–10 символов при кегле библии), `[ПОДСКАЗКА: …, ≤ N символов]` в `ux/ftue.md`, лимиты реплик и выборов в плане Ink.
- Длина считается без rich-text тегов (`<b>`), плейсхолдер — за 4 символа (`--ph-len`).
- `--pseudo 0.35`: исходник удлиняется на 35 % + 2 скобки и проверяется против `max:N` — переполнение видно до перевода. RU / PL / DE длиннее EN на 20–35 %.

## 3. Сбор ключей (scan)
| Где | Что считается ключом |
|---|---|
| `ux/hud.md` | колонка Loc key |
| UXML | `text="ui.x"`, `entry="ui.x"` (привязка `LocalizedString`) |
| C# | строковый литерал `"<префикс>.<имя>"`, где префикс есть в таблицах или hud.md |
| Ink | `#id:<key>` на строке с текстом |

Литерал вместо ключа (LC5): в UXML `text="…"` с буквами, не похожий на ключ; в C# `.text = "…"` с буквами; в Ink строка с текстом без `#id:`. Исправляет владелец: UXML / C# — `ui-build`, `.ink` — `ink-slice`.

## 4. Live (пакет установлен)
1. Localization Settings (Edit → Project Settings → Localization), локали из списка языков, Pseudo-Locale для проверки.
2. String Table Collection на каждый CSV; расширение CSV коллекции → импорт `design/loc/<Table>.csv` (меню коллекции или editor-скрипт через MCP). После импорта — экспорт обратно и сравнение: ключей столько же.
3. UI Toolkit: у элемента из hud.md привязка `LocalizedString` (таблица + ключ) к `text`; атрибут `text="ui.x"` остаётся как видимый плейсхолдер в UI Builder.
4. C#: `LocalizedString` / `GetLocalizedString` по ключу из констант, без литералов текста.
5. Смена языка в play mode и Pseudo-Locale → скриншоты 2–3 разрешений (`ui-build` / `qa-run visual`): текст не обрезан, не вылез за зону, шрифт содержит глифы (кириллица, диакритика PL).
6. Лог `design/build/loc.log.md`: таблицы, ключей, языков, `mt`, переполнений, путь к скриншотам.

## 5. Plan (пакета нет)
CSV и `check_loc.py` без Unity; в логе `mode: plan` и чеклист live-шагов. Установку пакета предлагает скилл, ставит — после «да» человека (Package Manager → Unity Registry → Localization).

## 6. Проверки `check_loc.py`
| ID | Что | Уровень |
|---|---|---|
| LC1 | ключ из hud.md / UXML / C# / Ink нет ни в одной таблице; пустой исходник | FAIL |
| LC1 | пустой перевод | WARN |
| LC2 | ключ таблицы нигде не используется | WARN |
| LC3 | длина значения (или псевдо-исходника) > `max:N` | FAIL |
| LC4 | набор плейсхолдеров `{…}` ≠ исходнику | FAIL |
| LC5 | литерал вместо ключа в UXML, C#, Ink | FAIL |
